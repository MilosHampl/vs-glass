VS Glass

Colourless, multilayer Apple Liquid Glass for VS Code, built for a transparent window first — refractive edges, specular highlights, and layered glass planes; tint is optional.

The centrepiece

Live refraction demo

This pane is built exactly like Layer 2's real widgets: an SVG feDisplacementMap, driven by a displacement map generated on this page at runtime (canvas → data URL, mirroring src/lens.ts), bends the code underneath toward the pane's centre at the rim, with a frosted body and a specular ring on top. Drag it.

// src/lens.ts — the displacement profile behind this exact demo
export function profile(distToEdge: number, edge: number, power = 2) {
  if (distToEdge >= edge) return 0;
  const t = 1 - distToEdge / edge;
  return Math.pow(t, power);
}

// R = x-displacement, G = y, B = rim weight, 128 = neutral
for (let y = 0; y < mh; y++) {
  for (let x = 0; x < mw; x++) {
    const rim = Math.pow(rimRaw, 0.8);
    data[i]   = 128 + px * 127; // R
    data[i+1] = 128 + py * 127; // G
    data[i+2] = rim * 255;       // B
  }
}

const glass: Elevation = {
  solid: '#272d37',
  specular: { hi: 0.5, mid: 0.16, lo: 0.04 },
};

Drag the pane (or focus it and use arrow keys) to see the code bend under the rim as it moves.

Optical signature

The eight optics

Apple names eight optical properties that define Liquid Glass (HIG Materials + WWDC25 "Meet Liquid Glass" / "Build a SwiftUI app with the new design"). Here's Apple's own language for each, next to how VS Glass reproduces it in a text editor that has no z-depth renderer, no light source, and no access to what's behind the window.

1. Lensing / refraction

Reproduced
"Lensing… dynamically bends, shapes, and concentrates light in real time."WWDC25 — Meet Liquid Glass

How: a canvas-generated displacement map feeds an SVG feDisplacementMap (the same technique as the demo above) on every overlay that overlaps code — quick input, suggest, hovers, dropdown lists, notifications, find, sticky scroll — and on the floating chrome cards (context menus are the one overlay VS Code isolates in a shadow root, so they keep the theme's colours only). The refracted rim replaces what's behind it rather than adding a second copy, so there's no double image. The window's own top and bottom edges bend the title bar and status bar toward the window centre the same way, and the editor card's bottom edge bends the last visible code lines.

2. Specular edge highlight

Reproduced
"Light sources… shine on the material producing highlights that respond to geometry… defining its silhouette."WWDC25 — Meet Liquid Glass

How: a conic-gradient ring from a virtual top-left light, cut to a hairline with mask-composite: exclude, with alpha tuned per elevation (chrome → overlay).

3. Material thickness

Reproduced
"It casts deeper, richer shadows… and a softer scattering of light."WWDC25 — Meet Liquid Glass

How: layered box-shadow — inset top light, inset bottom dark, soft + tight outer contact shadows — keyed to the palette's shadow colour per elevation level, plus a bevel band (light hairline, dark band, faint light line) just inside every rim so edges read as thick glass even over a flat backdrop.

4. Vibrancy

Approximated
"Symbols and glyphs on top of Liquid Glass… flip from light to dark… to maximize contrast."WWDC25 — Meet Liquid Glass

How: four static label alpha tiers (macOS's 85/55/26/10% ramp) that composite against whatever sits underneath — not a true per-pixel contrast flip, which VS Code's text renderer has no hook for.

5. Floating layered panes

Reproduced
"Liquid Glass forms a distinct functional layer… that floats above the content layer."Apple HIG — Materials

How: VS Code 1.136's modernUI floating-card layout (sidebar / panel / aux bar), elevation shadows, and one window-wide glass slab — the whole workbench gets its own rounded rim, with cards, widgets and controls nested inside on one concentric radius ladder.

6. Concentric geometry

Reproduced
"Concentric shapes calculate their radius by subtracting padding from the parent's."WWDC25 — Get to know the new design system

How: cornerRadius.* tokens overridden window-wide; inner elements (list rows, inputs, tabs) get radius = parent − padding instead of a fixed value.

7. Adaptive tint

Approximated
"By default, Liquid Glass has no inherent color, and instead takes on colors from the content directly behind it."Apple HIG — Color

How: the default material is colourless. In transparent-window mode, the OS genuinely blurs your real desktop behind the window — real adaptive tint, just supplied outside VS Glass's own CSS. Over an opaque window, an optional neutral-smoke addon (no hue) gives saturate() real pixels to process instead; eight optional tint addons layer a fixed coloured film on top of either mode.

8. Liquid response

Approximated
"Liquid Glass responds to interaction by instantly flexing and energizing with light… gel-like flexibility."WWDC25 — Meet Liquid Glass

How: deliberately minimal, by the owner's explicit direction — the specular sheen on every surface is static, nothing moves on hover. The only response anywhere in Layer 2 is a quick press scale on buttons and pills, a pop-in entrance on floating widgets, and a focus glow on list rows: real CSS transitions, not a physics-based spring; disabled under prefers-reduced-motion.

Four looks, one material system

Variants gallery

One palette, four knob settings — blur, saturation, lens strength and aberration all scale together, the way Apple's own Regular/Clear split does.

Modes & tints

Layer 2 is one default plus five optional addon families, loaded after glass.css.

Transparent window (default)

glass.css alone. Assumes the window itself is see-through (Vibrancy Continued) — the workbench paints only a thin smoky film plus any tint; the window is one rounded glass slab.

Wallpaper (addon)

glass-wallpaper.css, loaded after glass.css. A neutral smoke backdrop — no hue, only luminance — for a window that stays opaque.

Tints (addons)

One of eight tints/glass-tint-<id>.css files, loaded after glass.css (and after glass-wallpaper.css, if used). A thin coloured film, combinable with either mode above.

Density (addons)

One of six density/glass-density-<percent>.css presets (0, 25, 50, 75, 150, 200; 100 is the default, now itself almost clear), loaded after glass.css. One variable, --vsg-density, scales the base window — the window film, editor content, and chrome — from fully clear (0) to opaque-ish (200). Floating widgets (palette, hovers, suggest, notifications) are exempt on purpose and keep their own fixed, readable body. Combinable with any mode or tint above.

Lens & aberration (addons)

Two real, generated addon families that re-emit the same SVG lens filters at a different strength: lens/glass-lens-soft.css or -strong.css (a gentler or heavier rim bend), and aberration/glass-aberration-off.css, -subtle.css or -strong.css (no fringing up to heavy red-to-blue fringing). Load after glass.css; combinable with everything above.

What Layer 2 actually adds

Layer 1 vs. Layer 1 + 2

The theme alone (Layer 1) gives you the right colors. Without Layer 2, those colors sit on flat rectangles — no bending, no shine, no depth. Layer 2 is what makes it look like glass.

Same theme, same colors, same window — the only difference is whether glass/glass.css is injected. Layer 2 adds the lensing at every edge, a specular ring keyed to a virtual top-left light, layered contact shadows for material thickness, and one glass slab around the whole window that the floating cards nest inside.

Getting it running

Install

1. The theme

  1. Open the Extensions view in VS Code, search "VS Glass", click Install — once it's on the Marketplace.
  2. Or download the .vsix from Releases and run code --install-extension vs-glass-1.0.0.vsix.
  3. Or, in the Extensions view, use Install from VSIX… and pick the downloaded file.

2. Pick your theme

  1. Open the Command Palette → Preferences: Color Theme.
  2. Choose Glass Regular Dark, Regular Light, Clear, or Opaque.
  3. This alone gives you the correct colors — no extra steps, no file patching.

Enable the glass effects (Layer 2)

The theme gives you colors; Layer 2 (glass/glass.css) gives you the actual lensing, specular rings and thickness. VS Code has no supported extension point for CSS injection, so every route works by patching a file inside VS Code's own installation. Full instructions: glass/install.md ↗.

Route A

Custom CSS and JS Loader

The be5invis.vscode-custom-css extension (1.19M+ installs). Point vscode_custom_css.imports at glass/glass.css, run Enable Custom CSS and JS, restart. Best if you're actively editing the CSS — fastest edit-reload-look loop.

Route B

scripts/inject.sh

A bash script in this repo that appends glass.css straight into VS Code's own workbench.desktop.main.css and fixes the integrity checksum for you. No extension, no CSP change — the lowest-risk route for everyday use. Run bash scripts/inject.sh install, then fully quit and reopen VS Code.

Route C

Vibrancy Continued

The intended setup: the only route that makes the whole VS Code window genuinely see-through, using native OS blur — glass.css alone is built for it. Lensing still only shows where glass overlaps content VS Code itself painted — CSS can't bend the desktop behind a transparent window.

Honestly: all three routes patch a file inside your VS Code.app installation — there's no supported extension point for this kind of CSS injection — and every one trips VS Code's own file-integrity check, which shows a harmless "Your Code installation appears to be corrupt" notice the first time (each route explains how to dismiss it permanently). All three need to be re-applied after every VS Code update, since the updater overwrites the patched files. Route A additionally removes the workbench's Content-Security-Policy for the life of the window while it's enabled, to let its injected styles run without a trusted-types policy — a real, if narrow, reduction in defense-in-depth that's reasonable to accept deliberately, just not by accident. Route B needs no CSP change at all. Glass Opaque never applies Layer 2, by design — it's the flat, distraction-free option if you'd rather skip all of this.
